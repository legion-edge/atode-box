# 端末内保存（Issue #3）

`LocalRepository` は Inbox Item と生活時間設定の保存ポートです。保存・更新・物理削除・設定変更の `Future` は、ファイル書き込み完了後にだけ正常終了します。呼び出し側は例外時に成功表示せず、再試行できるよう入力を保持してください。画面と通知の接続は後続 Issue で行います。

保存先は iOS の Application Support、Android のアプリ専用 `filesDir` にある `atode_box.json` です。ネイティブの小さな MethodChannel で保存先だけ取得し、追加パッケージは使いません。JSON 1文書を一時ファイルに同期書き込みしてから差し替えます。差し替え中の中断では `.bak` を読み込めます。破損した現行文書や未知の将来スキーマは黙って初期化せず、読み込みエラーとして返します。

`schema_version` は現在 1。未指定を 0 として読み込み、欠けている後発フィールドに既定値を補い、次回の正常な書き込みで 1 に更新します。今後は版ごとの移行を追加し、旧版の原文を保持し、未来版を開いた場合は書き込まない方針です。スキーマ 0 は移行検証用の旧形式であり、リリース済みアプリの既存DBはありません。

`original_text` と `saved_at` は更新時に変更できません。状態は `active` / `completed` / `deleted`。削除状態と物理削除は別操作で、「あとで」は `active` の `snooze_count` と `next_notify_at` を更新します。`needs_processing` は分類・通知準備の後続処理用です。通知日時の決定や設定画面はここでは扱いません。

制約: 全件を単一 JSON に保持するため、データ量が大きくなった時はデータベース移行が必要です。ファイルは端末のアプリ専用領域ですが暗号化は行いません。個人データや保存内容をログには出しません。
