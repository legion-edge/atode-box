# MVPと開発フェーズ

更新日: 2026-09-27。

## 体験の核

「何でも入れるだけ。ちょうどいい時に思い出させる。」入力時にカテゴリ、フォルダ、通知日時を選ばせない。ホームは大きな自由入力欄、登録、明示操作の「貼り付けて追加」、通知一覧と設定への導線だけを中心にする。登録成功の短い表示を出し、分類完了を待たせない。

## Phase 1: 自分で使える

GitHub Issueを少なくとも次に分割する: (1)初期構成、(2)ホーム入力、(3)ローカルデータモデル、(4)基本分類、(5)生活時間設定、(6)通知ルールエンジン、(7)OSローカル通知、(8)通知一覧、(9)詳細画面。各Issueは独立した範囲と検証条件を持つ。

計画Issue: [Phase 1 #1〜#9](https://github.com/legion-edge/atode-box/issues?q=is%3Aissue+%22Phase+1%22)、[Phase 2 #10〜#15](https://github.com/legion-edge/atode-box/issues?q=is%3Aissue+%22Phase+2%22)、[Phase 3 #16〜#21](https://github.com/legion-edge/atode-box/issues?q=is%3Aissue+%22Phase+3%22)。

Issue #1のレビュー・main反映後は、保存の土台となるIssue #3に着手する。ホーム入力Issue #2はIssue #3の保存ユースケースへ接続する。

完了条件は、登録 → 分類 → 生活時間に合わせた通知 → 開く／完了／あとで → 通知一覧で確認、がiOS / Androidで成立すること。通知は1件ずつ、カテゴリ別文面、3アクションとする。「あとで」は日時選択なしの1タップ。URLを開いても自動完了しない。完成後にDiscordから移行して1〜2週間使い、操作数や再通知の適切さを確認する。

初期設定は帰宅開始18:00、帰宅後19:00、土日と日本の祝日を休日とし、初回起動時に「このまま使う」「設定を変更する」を提示する。祝日判定と通知時刻の細部は各IssueのAcceptance Criteriaで決定する。

Issue #5では生活時間と休日の選択を端末内に保存する。Issue #6で [通知予定ルール](SCHEDULING.md) と保存済みactive項目の再計算を追加した。設定と予定の保存が成功した場合だけ `SettingsChange` を返し、`scheduleChanged` が真なら再計算する。初回案内の完了フラグだけの変更では再計算しない。OS通知の登録・更新は後続Issueで実装する。

## Phase 2: 毎日快適に使える

OS共有シート、OpenAIを使った分類、読む／見る／買う／行くの推定改善、休日・祝日判定の改善、偶然の再発見を個別Issueで扱う。AIがなくてもローカルの基本機能は動く。共有と推定が操作数を増やさないことを確認する。

## Phase 3: 販売可能

AWSバックエンド・認証・同期、OpenAIのサーバー側実行、スマートスケジューリング、通知UX、課金、Privacy Policy / Terms、リリース品質、App Store / Google Play対応を個別Issueで扱う。外部サービスと個人データに関わる仕様は実装Issueで明確にする。

## 対象外

高機能Todo、プロジェクト／フォルダ／コレクション／手動タグ／複雑な優先度管理、AI要約中心の体験、PCブラウザ拡張、Phase 1のデスクトップ版とクラウド同期。機能追加は「適切なタイミングで思い出すことを改善するか」で判断する。
