# ドメイン

更新日: 2026-09-27。名称と不変条件を先に揃え、具体的な保存形式はIssue #3相当で決める。

| 概念 | 意味 | 主な値・不変条件 |
| --- | --- | --- |
| Inbox Item | 雑に保存した1件 | ID、原文、任意のタイトル／URL、保存時刻、カテゴリ、状態、次回通知、あとで回数。原文は失わない |
| Category | 内容の大まかな種類 | `read` 読む、`watch` 見る、`go` 行く、`buy` 買う、`do` やる、`idea` アイデア、`memo` メモ |
| Notification Context | 生活の中で通知を受ける場面 | 帰宅開始／帰宅中、帰宅後、夜、翌日夜、休日の前日夜、休日昼、休日夜、1週間後 |
| Schedule | 次の通知予定 | 端末のタイムゾーンを考慮した日時、選んだContext、計算根拠。過去を指さない |
| Snooze | 「あとで」による再通知 | `snooze_count` を増やし `next_notify_at` を更新。独立したstatusは作らない |
| User Lifestyle Settings | 生活時間と休日の設定 | 帰宅開始18:00、帰宅後19:00、土日と日本の祝日を初期値とする。初回に案内する |

## 状態と操作

状態は原則 `active`、`completed`、`deleted` の3つ。登録は `active`、通知で「開く」は状態を変えない。「完了」は `completed`、「あとで」は `active` のまま再予定する。削除は通知アクションでは提供しない。詳細画面では必要に応じて編集・削除を行う。

分類はユーザーに入力を求めず自動で行う。曖昧な内容を無理に細分化せず `memo` へ寄せる。カテゴリは内部値と日本語表示を分け、画面では淡い色、アイコン、文字を併用する。

Phase 1の基本分類は `BasicClassifier` が原文だけを使ってオフラインで行う。既知の動画ホスト（YouTube、Netflix）と、少数の明確な日本語表現を判定する。URLのパスや未知のホストから内容を推測せず、複数カテゴリの手掛かりがあれば `memo` にする。結果には判定理由（ホスト、文言、競合、手掛かりなし）と一致した根拠を含む。保存時にカテゴリを記録するが、`needs_processing` は通知準備が残るため維持する。既存の保存済みカテゴリは読み込み時に再分類しない。`CategoryPresentation` が7種の日本語名・アイコン・色を定義し、登録確認には3つを併用する。

通知一覧は処理待ちタスクの管理画面ではなく、残件と予定を確認する場所。今日、明日以降、休日を主フィルターとし、1週間後以降、完了済みを追加する。フィルターの境界は端末ローカル日付で計算する。

## 仮定と未決定

- 「夜」の既定時刻、通知が重なる場合、休日の前日と連休の扱いは通知ルールIssueで決める。
- 祝日データの供給方法、振替休日・国民の休日、年をまたぐ更新方法はそのIssueで検証する。祝日を単なる週末判定で代用しない。
- URL先の本文取得・推定時間はPhase 2候補。Phase 1で推定不能な時は既定ルールを使う。
