# ローカル通知（Phase 1 / Issue #7）

確認日: 2026-09-29。

端末内の保存データを正本とする。保存時に項目へOS通知用の整数IDを割り当て、予定UTC時刻を含むペイロードでOS予約と照合する。予約の追加・取消は保存、設定変更、通知アクション、起動、アプリ復帰後に行う。Androidの再起動時はプラグインのBootReceiverも予約を復元する。iOSは保留中のローカル通知をOSが保持し、アプリ起動・復帰時に再照合する。

1項目に次回通知1件を予約する。カテゴリごとに日本語の短いタイトルと本文を使い、保存内容そのものはロック画面に出さない。iOSの保留通知上限に合わせ、近い順に最大64件をOSへ登録する。65件目以降はアプリの次回起動・復帰時に空きがあれば登録する。Androidは省電力状態でも動く不正確なアラームを使うため、表示が予定時刻から遅れることがある。正確なアラームの追加権限は要求しない。

初回案内の後、通知が無効な場合にホームで理由と許可ボタンを表示する。一度拒否した利用者には、端末の設定で「あとでボックス」の通知をオンにする方法も示す。拒否しても登録と保存済みデータの読込は続く。OSで後から許可した場合はアプリ復帰時に予約を作り直す。保存後のOS予約失敗は項目の保存を取り消さず、画面で伝えて次回起動・復帰時に再試行する。

通知本体または「開く」は保存内容を表示し、URLがあれば外部アプリで開く。項目はactiveのままで、URLを開いても完了しない。「完了」はcompletedとして保存し、次の通知予約を取り消す。「あとで」は画面を追加せず1回の操作でIssue #6の再予定を保存し、次回通知を予約する。3つのアクションはアプリを前面に出して処理する。保存失敗時は状態を進めず、画面に失敗を示す。通知アクションは順番に照合・反映し、古い通知や同じペイロードの「完了」「あとで」の重複配信は保存済みの予定UTC時刻が一致しない限り無視する。

端末のタイムゾーン名または現在のUTCオフセットが変わった場合、起動・復帰時にactive項目の予定を再計算する。OSで予約された通知と保存データは単一のトランザクションにできないため、再照合で差を埋める。アプリが一度も起動・復帰しない間のタイムゾーン変更や、65件目以降の予約は即時には反映できない。

使用する依存は `flutter_local_notifications`（iOS/Android通知とアクション）、`timezone`（プラグインが要求する日時型）、`url_launcher`（開く操作のURL遷移）の3つ。通知の時刻は既存のルールエンジンがUTCで決定するため、追加のタイムゾーン取得プラグインは使わない。
